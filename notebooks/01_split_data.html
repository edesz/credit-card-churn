Pre-Process and Split Customer Churn Data

Author

edesz

Last Updated

May 7, 2026

About

In this first step of the analysis, we will use an ETL (Extract-Transform-Load) workflow to load, pre-process and split the sample of raw credit card customer churn data. The raw data is provided to us as a .xlsx file in our private R2 bucket.

In order to minimize memory consumption, we will specify datatypes when loading the raw data during the extract step.

In the transform step, the loaded data is then pre-processed as follows

  1. change all column names to lowercase
  2. drop duplicates across all columns
  3. drop duplicates across the client ID column (clientnum)
  4. map label column from string to integer, with 0 indicating the customer did not churn and 1 indicating churn

Finally, in the load step, all data splits are exported to .parquet files on R2.

NoteOutputs

The following files are created with processed customer data

  1. train.parquet.gzip
    • customers in the train data split
  2. train.parquet.gzip
    • customers in the validation data split
  3. test.parquet.gzip
    • customers in the test data split

Transform

Pre-Process Data

We will now perform the following basic data cleaning operations

  1. change all column names to lowercase
  2. drop duplicates across all columns
    • Duplicate records can skew analysis and model training by giving more weight to repeated entries, which biases the model. This step ensures that each customer contributes equally to the learning process by dropping rows where a client’s attributes have been duplicated
  3. drop duplicates across the client ID column (clientnum)
    • drops rows where a client’s ID has been duplicated, to ensure there were no repeated entries for the same customer
  4. rename columns with normalized columns defined in a dictionary column_renamer_dict
  5. change label column from string to integer
df = (
    df.rename(columns=str.lower)
    .drop_duplicates(subset=None)
    .drop_duplicates(subset=["clientnum"])
    .rename(columns=column_renamer_dict)
    .assign(
        is_churned=lambda df: (
            df["is_churned"].map(label_mapper).astype("int8[pyarrow]")
        )
    )
)
with pd.option_context("display.max_columns", None):
    display(df.head(1))

A summary of the processed data is shown below

The pre-processed data has the same number of rows as the raw data. This indicates no duplicates were present in the raw data.

As mentioned above, we created a new binary column named is_churned based on the existing Attrition_Flag column. This converts the text labels as follows

  1. Existing Customer is mapped to 0 (customer did not churn)
  2. Attrited Customer is mapped to 1 (customer did churn)

This is essential because machine learning models require numerical values to perform classification tasks. Once this conversion was done, the original Attrition_Flag column is no longer needed and so it was dropped.

Split Data

Now, we will create the following data splits

  1. training
    • will be used to determine the best ML model, including
      • decision threshold tuning using cross-validation
      • hyperparameter tuning, with best decision threshold, using cross-validation
  2. validation
    • will be used to determine best customer segmantation using business metrics
  3. test
    • will be used to evaluate
      • performance of best ML model using ML metrics
      • business metrics to be expected in production
# get train and test split
df_train, df_test = train_test_split(
    df,
    test_size=size_val / (1 - size_val),
    random_state=88,
    shuffle=True,
    stratify=df[label],
)

# get validation split
df_train, df_val = train_test_split(
    df_train,
    test_size=size_val / (1 - size_val),
    random_state=88,
    shuffle=True,
    stratify=df_train[label],
)

# show number of observations in each split
n_rows_total = len(df_train) + len(df_val) + len(df_test)
n_rows_cv = int(len(df_train) / n_cv_folds)
frac_rows_cv = 100 * n_rows_cv / (len(df_train) + n_rows_cv)
frac_rows_val = 100 * len(df_val) / (len(df_train) + len(df_val))
frac_rows_test = (
    100 * len(df_test) / (len(df_train) + len(df_val) + len(df_test))
)
print(
    f"Training Size: {len(df_train):,}\n"
    f"Cross-Validation Fold Size (Estimate): "
    f"{n_rows_cv:,} ({frac_rows_cv:.2f}%)\n"
    f"Validation Size: {len(df_val):,} ({frac_rows_val:.2f}%)\n"
    f"Test Size: {len(df_test):,} ({frac_rows_test:.2f}%)"
)
val_fold_diff = len(df_val) - n_rows_cv
val_fold_diff_pct = 100 * val_fold_diff / n_rows_cv
Markdown(
    f"""The sizes of the cross-validation fold (approximately {n_rows_cv:,}) validation split
    (approximately {len(df_val):,}) are reasonably clos to each other. Ideally, if the
    `test_size` is fixed across both splits (train+validation and train+test), the sizes of the
    cross-validation fold, validation split and test split would be identical. Due to the non-
    rounded size of the raw data, there are {val_fold_diff} (or ~{val_fold_diff_pct:.0f}%) fewer
    observations in the validation fold than in the test fold. We will assume this difference is
    acceptable and further fine-tuning of the split sizes will not be performed.
    """
)
CautionAccount for Class Imbalance when Splitting Data

startify=True was used to create splits due to the known class imbalance of the labels (is_churned) column in the data.

From adding up the totals, it is also reassuring that all observations from the raw data have been used in the data splits, as expected. This is verified below

assert len(df) == n_rows_total
ImportantRationale for Performing Pre-Processing Data Before Splitting

The simple pre-processing steps in the previous section could be performed without leaking data from the validation split into the train split, and similarly from the test into the combined train+validation split. There were no missing values to be imputed and no duplicates so our pre-processing workflow did not learn patterns from the data to be used in model validation or evaluation to clean the training data. For this reason, we were able to pre-process the data as we did before splitting it in this section.

Export training data split to train_data.parquet.gzip

r2io.export_df_to_r2(s3_client, df_train, bucket_name, r2_key_train, False)

Export validation data split to validation_data.parquet.gzip

Export test data split to test_data.parquet.gzip
