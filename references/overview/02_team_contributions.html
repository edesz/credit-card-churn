Code Implementation

This section contains the notebooks that were developed by team members as part of the first four implementation phases above.

Project Scoping

The 02_scoping.ipynb notebook (link, view) was used to perform quantitative analysis to scope out this project. It estimated the quantitative impact of credit card churn to quantify the problem facing the client using two KPIs.

Analysis

The following notebooks were developed as part of the Analysis phase

  1. Preprocess and Split Raw Data
    • create train, validation and test splits
    • 01_split_data.ipynb (link, view)
  2. EDA
    • perform exploratory data analysis (EDA) on the processed combined training and validation data split
      • preliminary versions
        • 03_eda_v0.ipynb (link, view)
        • 03_eda_v1.ipynb (link, view)
      • final version
        • discuss implications of class imbalance
        • determine candidate data transformations of categorical and ordinal features before performing ML development
        • develop a hypothesis about useful features to predict churn, by feature type
        • 03_eda_v2.ipynb (link, view)

ML Model Development

The notebooks below were written by team members as part of stream 1 of the ML Model Development phase

  1. ML Validation - Cost-Sensitive Learning
    • develop a parameterized workflow to run ML experiments using linear models and tree-based models with the Metaflow framework
    • this notebook was programmatically run with different input parameters for each ML experiment on the combined training validation data split
    • 04_run_validation_experiments.ipynb (link, view)
  2. Get best combination of ML model, features and feature pre-processing from results of validation experiments in the previous step
    • 05_get_best_validation_experiment.ipynb (link, view)
  3. ML Evaluation
    • evaluate best ML model performance on unseen (test split) data
    • 06_evaluate.ipynb (link, view)
  4. ML Inference
    • perform inference on all available customer data
    • 07_inference.ipynb (link, view)
  5. Estimate Business Metrics on inference predictions
    • the following notebooks used inference predictions to identify the top customers at risk of canceling credit card services, while constrained by two budget scenarios, using
      • ROI
        • 08_estimate_cohort_size_using_roi.ipynb (link, view)
      • (Net) Savings
        • 09_estimate_cohort_size_using_savings.ipynb (link, view)
  6. Inference Customer Profiling
    • create profiles for all customers predicted to be at risk of canceling credit card services
    • 10_get_at_risk_customer_profiles.ipynb (link, view)
  7. Interpret Best Machine Learning Model
    • use SHAP to globally explain predictions made by the best ML model when using the best features identified during model validation in step 1. above, separately for customers predicted to churn and be retained
    • 11_interpret_model_predictions.ipynb (link, view)

The 13_production_ml_pipeline.ipynb notebook (link, view) implements the end-to-end pipeline developed during stream 2 of the ML Model Development phase. It contains the following

  1. comprehensive ML pipeline with XGBoost, LightGBM, RandomForest
  2. SHAP interpretability, CLV calculator, ROI optimization

It provides a production-ready infrastructure with the following custom Python modules

  1. src/models
  2. src/business
  3. src/evaluation
  4. src/utils

Data Validation

The 12_validate_data.ipynb notebook (link, view) used a custom data model to validate the raw credit card customer data. It used the Python pandera package to develop the data schema.
